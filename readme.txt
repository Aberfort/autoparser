Автоматично парсить статті з вказаних RSS/sitemap-джерел, унікалізує текст через AI (Gemini або OpenAI) і публікує готовий допис у Gutenberg — без ручного копіпасту.

== Description ==

**Autoparser** — інструмент для агенцій та видавців, які ведуть кілька сайтів на новинному чи тематичному контенті й хочуть автоматизувати рутину «знайти джерело → переписати унікально → опублікувати».

Плагін:

1. **Знаходить нові матеріали** у вказаному RSS/Atom-фіді або XML sitemap (включно з sitemap index).
2. **Переписує текст** через обраний AI-провайдер (Google Gemini або OpenAI GPT) за вашим власним промптом, зберігаючи сенс і структуру оригіналу.
3. **Публікує** готовий допис у редакторі Gutenberg — з категоріями, автором, мініатюрою (автоматично з першого зображення джерела) і, за бажання, шаблонами SEO-заголовка/опису (сумісно з Yoast SEO).
4. Працює **за розкладом** (через Action Scheduler) або вручну — з адмінки, через REST API чи WP-CLI.

= Ключові можливості =

* Підтримка RSS/Atom, XML sitemap та sitemap index як джерел.
* Два AI-провайдери «з коробки»: Google Gemini та OpenAI (потрібен власний API-ключ кожного сервісу).
* Кастомний CSS-селектор початку/кінця контенту для сайтів без коректного RSS.
* Захист від дублів: кожен фід пам'ятає, які URL уже імпортовано.
* Керування кількома незалежними «лентами» (джерелами) з окремими налаштуваннями кожна.
* Імпорт/експорт списку джерел у форматі OPML — зручно при перенесенні агенцією набору фідів між сайтами.
* Опційна інтеграція з WPML і Polylang — якщо для стрічки вказано мову, а один із цих плагінів активний, опублікований допис отримає відповідну мову автоматично.
* WP-CLI: `wp autoparser run [--feed=<id>]` та `wp autoparser test-selector --url=<url> [--selector=<css>]` — перевірка CSS-селектора без збереження стрічки.
* CSS-селектор — необов'язковий: якщо порожній чи не знайдений, автоматично пробуються типові варіанти (`article`, `main`, `.entry-content` тощо), а кнопка «Перевірити селектор» у формі стрічки показує, що саме буде витягнуто, ще до збереження.
* REST API під власним namespace `autoparser/v1`.

= Для кого =

Для агенцій і власників кількох контентних/новинних сайтів, яким потрібен передбачуваний, керований потік унікального контенту без ручної роботи копірайтера на кожну статтю.

== External services ==

Цей плагін звертається до сторонніх сервісів **лише за наявності відповідного ключа/налаштування, які ви вводите самостійно**, і лише в межах явно описаних дій:

* **Google Gemini API** (`generativelanguage.googleapis.com`) — використовується для рерайту заголовка й тексту статті, якщо у Налаштуваннях вказано Gemini API Key і обрано провайдера Gemini. Плагіну передається текст оригінальної статті та ваш промпт. Дані передаються лише під час ручного чи запланованого запуску конкретної стрічки.
  [Умови використання](https://ai.google.dev/gemini-api/terms) · [Політика конфіденційності Google](https://policies.google.com/privacy)

* **OpenAI API** (`api.openai.com`) — аналогічно, використовується для рерайту, якщо обрано провайдера OpenAI і вказано ключ.
  [Умови використання](https://openai.com/policies/row-terms-of-use) · [Політика конфіденційності](https://openai.com/policies/row-privacy-policy)

* **Джерело RSS/sitemap, яке ви самі вказуєте у налаштуваннях стрічки** — плагін надсилає звичайний HTTP GET-запит на цей URL для отримання списку статей і їхнього HTML.

* **r.jina.ai** (вимкнено за замовчуванням, вмикається окремим перемикачем «Резервний проксі» у Налаштуваннях) — якщо ви явно увімкнули цю опцію, використовується як резервний спосіб отримати вміст сторінки, коли пряме звернення до вказаного вами джерела повернуло помилку 403/503 (наприклад, джерело блокує автоматичні запити). У такому разі URL джерела передається на `r.jina.ai` для проксі-фетчу.
  [Політика конфіденційності r.jina.ai](https://jina.ai/legal/)

Жодні дані не передаються третім сторонам поза цими явно описаними сценаріями, і жодних даних не збирається чи не передається на сервери автора плагіна.

== Installation ==

1. Завантажте ZIP-архів плагіна через «Плагіни → Додати новий → Завантажити плагін».
2. Активуйте плагін.
3. Перейдіть у меню **Autoparser → Налаштування** і вкажіть API-ключ Gemini та/або OpenAI.
4. Перейдіть у **Autoparser → Ленти** і додайте перше джерело (RSS/sitemap URL, CSS-селектор контенту, промпт рерайту).
5. Натисніть «Запустити» для тестового прогону або дочекайтесь запланованого часу.

== Frequently Asked Questions ==

= Які джерела контенту підтримує плагін? =

RSS/Atom-фіди, XML sitemap та sitemap index. Якщо у налаштуваннях стрічки залишити URL порожнім — плагін генерує контент виключно через AI (окремий сценарій, без парсингу стороннього сайту).

= Які AI-провайдери підтримуються і чи є вони безкоштовними? =

Google Gemini та OpenAI GPT. Обидва вимагають власного платного/лімітованого API-ключа — плагін сам по собі не надає доступ до AI, лише інтегрується з вашим акаунтом.

= Чи зберігаються мої API-ключі в базі даних? =

Так, у таблиці `wp_options` (опція `autoparser_settings`). Ключі передаються виключно напряму до Gemini/OpenAI під час рерайту і ніде більше не використовуються.

= Що станеться з моїми даними, якщо я видалю плагін? =

Таблиці стрічок і мапінгу постів та опція налаштувань видаляються автоматично. Файли логів у `wp-content/uploads/autoparser/` не видаляються автоматично — за потреби приберіть цю теку вручну.

= Чи сумісний плагін з мультисайтом? =

Так, на рівні окремого сайту мережі — кожен сайт має власні незалежні стрічки. Централізованого керування кількома сайтами мережі з одного екрана наразі немає.

= Як часто запускається парсинг? =

За розкладом Action Scheduler — раз на добу, у вказаний для конкретної стрічки час. Також можна запустити вручну кнопкою «Запустити» на сторінці стрічки в будь-який момент.

= Чи потрібен ACF або інші сторонні плагіни? =

Ні для базового сценарію «RSS → рерайт → публікація». Окремий модуль AI-прогнозів (футбол) вимкнено за замовчуванням і вмикається перемикачем у Налаштуваннях; він опційно використовує поля ACF Pro, якщо вони є, — за їх відсутності просто публікує звичайний текстовий допис.
